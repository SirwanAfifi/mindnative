# MindNative landing page

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

The existing landing page uses static HTML, CSS, and JavaScript.
The user selected GitHub Pages in the public MindNative repository for publication.

## Users

The page serves Mac users and developers equally.
Mac users need to understand the app before they get the source.
Developers need build instructions and a route to contribute.

## Product Purpose

MindNative is a native macOS mind map app.
Users connect ideas, add notes and attachments, and save maps as ordinary files.
The landing page shows the app and helps visitors get its source code.

## Positioning

Maps stay in user-controlled files.
The app combines native Mac document controls with optional on-device Apple Intelligence.
The app is open source under MIT and has no license fee.

## Operating Context

The app targets macOS 13 or later.
Its source requires Xcode 26 or later.
Apple Intelligence requires macOS 26 or later and a compatible Mac.
The public repository currently has source code but no packaged app release.

## Capabilities and Constraints

The app supports branches, cross-links, notes, tasks, attachments, search, layouts, and presentation mode.
It supports Markdown, OPML, FreeMind, XMind, PNG, PDF, and SVG interchange.
It uses optional Calendar, Reminders, and Shortcuts actions.
Links and update checks can make network requests.
Do not describe the app as offline-only.
Do not show an app download button that has no app package behind it.
Do not use the earlier App Store price or purchase claims.

## Brand Commitments

Keep the MindNative name and existing app icon.
Use the real app screenshots.
Use short sentences and direct instructions, following the user's ASD-STE100 preference.

## Evidence on Hand

The public source is at https://github.com/SirwanAfifi/mindnative.
Existing screenshot assets are in landing-page/assets and the public repository's docs/images folder.
The source contains privacy documentation and MIT and ZIPFoundation license notices.
There are no supplied testimonials, customer counts, awards, or performance benchmarks for page claims.

## Product Principles

- Show the app before visitors need to act.
- Make the source and build instructions easy to find.
- Explain local files and on-device AI accurately.
- Keep user and developer paths equally clear.
